**Blocking decisions (resolve before starting):**
1. **`status` / “active users”** — `profiles` has no `status` (or last-seen) column today (`id, email, full_name, role, created_at, updated_at` only). Decide: drop status/active requirements and use role + `created_at` stats only, **or** add a new migration for an explicit status enum/column (and indexes/filters) before UI work.
2. **Create/delete mechanism** — Decide whether Create uses Auth Admin (`lib/supabase/admin.ts`: invite vs set-password vs magic link) and Delete uses `auth.admin.deleteUser` (cascade to `profiles`), vs profile-row-only updates. This changes grants, RLS, and action shape.
3. **Signup default role** — `handle_new_user` still inserts `role = 'admin'` for every new Auth user. Decide whether Users CRUD create must set role explicitly and whether the trigger default should change to `viewer`/`editor` so new public signups are not admins.
4. **Dashboard access for non-admins** — `app/(dashboard)/layout.tsx` has no role check today. Decide whether only `admin` may enter `/dashboard/*`, or editors/viewers may enter but `/dashboard/users` stays admin-only.
