Prepare the app's SEO ecosystem before public/marketing pages go live. Covers metadata structure, sitemap/robots generation, Open Graph previews, structured data, and URL/image conventions.

**Scope:** public-facing marketing pages only (landing, programme, portfolio, insights/blog, FAQ, contact, apply, etc.). Authenticated app routes (`/dashboard`, `/api`, `/admin`, `/login`, `/signup`, auth callbacks) stay excluded from indexing.

### SEO Setup Checklist

- [ ] Root metadata configured in `app/layout.tsx` (title template, description, `metadataBase`, OG defaults, Twitter card)
- [ ] Per-page metadata (or `generateMetadata()`) added to every public/marketing page
- [ ] `app/sitemap.ts` created and dynamically includes all indexable public pages (locale variants)
- [ ] `app/robots.ts` created — disallows `/dashboard`, `/api`, `/admin`, `/login`, `/signup`, auth routes
- [ ] Static `app/opengraph-image.png` added for default social preview
- [ ] Dynamic OG image generation added for key dynamic public pages (if/when applicable)
- [ ] JSON-LD structured data added (Organization on landing; Article / FAQPage where relevant)
- [ ] All content images use `next/image`, not raw `<img>` tags
- [ ] URL structure uses readable slugs, not raw IDs (`slug` column present in relevant DB tables)
- [ ] Canonical URL set via `metadata.alternates` where duplicate-access paths exist (locale + bare slug redirects)
- [ ] One `<h1>` per page; correct heading hierarchy verified on key pages
- [ ] Alt text present on all meaningful images
- [ ] Google Search Console verified for the production domain
- [ ] Sitemap submitted to Google Search Console
- [ ] Lighthouse SEO score checked on landing (+ other priority marketing pages); target **90+**
