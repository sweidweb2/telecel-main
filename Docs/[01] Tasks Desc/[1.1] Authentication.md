Implement the full authentication system using Supabase Auth. This covers signup, login, supporting server actions, Zod validation, and route protection. This authentication foundation—relying on user_id and RLS policies—must be complete, robust, and tested before building on top of it.

### Authentication Task List

- [ ] Create migration for `profiles` table, set up trigger to auto-create profile on signup (linked to `auth.users`)
- [ ] Enable RLS (Row Level Security) and write policies for the `profiles` table
- [ ] Implement Zod validation schemas in `validations/auth.ts` for login and registration (email/password rules)
- [ ] Build `signUp()` server action in `actions/auth.ts`:
  - [ ] Validate input
  - [ ] Call `supabase.auth.signUp()`
- [ ] Build `signIn()` server action in `actions/auth.ts`:
  - [ ] Validate input
  - [ ] Call `supabase.auth.signInWithPassword()`
- [ ] Build `signOut()` server action in `actions/auth.ts`
- [ ] Create login form in `app/(auth)/login/page.tsx` using `react-hook-form` + Zod resolver
- [ ] Create register form in `app/(auth)/signup/page.tsx` using `react-hook-form` + Zod resolver
- [ ] Handle email confirmation & OAuth callback in `app/auth/callback/route.ts`
- [ ] Implement error handling:
  - [ ] Show proper toasts (using Sonner) for invalid credentials, duplicate email, and weak password
- [ ] Implement loading states during form submission (disable button, show spinner)
- [ ] After successful login, redirect user to their intended page
- [ ] Redirect to login if accessing a protected route while logged out (middleware or layout check)
- [ ] Ensure session is persistent across page refreshes (cookie-based; verify manually)
- [ ] Ensure logout clears session and cookies
- [ ] Write Playwright E2E test to cover: signup → confirm → login → access protected route → logout
- [ ] Manually test that duplicate signup email shows proper error message and does not crash
