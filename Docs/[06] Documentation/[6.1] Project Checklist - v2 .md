## And one thing I'd add specifically for AI agents

This is **extremely important**.

Don't only prepare a specification. Prepare **rules for the agent**.

For example:

```text
.ai/
├── PROJECT.md
├── ARCHITECTURE.md
├── BUSINESS-RULES.md
├── DATABASE.md
├── API.md
├── SECURITY.md
├── TESTING.md
├── UI.md
├── CONVENTIONS.md
└── TASKS.md
```

And define things like:

> Never access the database directly from the frontend.

> Controllers must not contain business logic.

> All business logic belongs in services.

> Every protected endpoint must perform authorization.

> Every database change requires a migration.

> Every new feature requires tests.

> Never invent an API endpoint that isn't defined in API.md.

> Never install a new library without checking whether an existing dependency already solves the problem.

> Never modify unrelated files.

> Before implementing a feature, inspect the existing architecture.

That turns your AI agent from:

**"AI that writes code"**

into:

**"AI developer working inside a defined engineering system."**

```text
                    PROJECT
                       │
       ┌───────────────┼────────────────┐
       ↓               ↓                ↓
    BUSINESS       ARCHITECTURE       DESIGN
       │               │                │
   workflows        frontend          pages
   rules            backend           layouts
   roles             database         components
   states            APIs              UX
   calculations      integrations      responsive
       │               │                │
       └───────────────┼────────────────┘
                       ↓
                  IMPLEMENTATION
                       │
       ┌───────────────┼────────────────┐
       ↓               ↓                ↓
    Security        Testing          Performance
       │               │                │
       └───────────────┼────────────────┘
                       ↓
                  INFRASTRUCTURE
                       │
              CI/CD → Staging → Prod
                       │
                       ↓
                OBSERVABILITY
                       │
              Logs / Metrics / Alerts
                       │
                       ↓
                 MAINTENANCE
```

**So no — the previous list wasn't the absolute maximum.**

But I also wouldn't make a 200-item checklist and force you to fill everything before starting. Some things are **project-definition requirements**, while others should be decided when the relevant feature appears.

The best approach is to create a **master project template** that separates:

**Must define before coding → Define per feature → Define during implementation → Production/operations.**

That gives you a practical system instead of a giant checklist nobody actually completes.
